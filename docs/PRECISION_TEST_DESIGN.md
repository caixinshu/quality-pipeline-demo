# 精准测试方案设计文档（L1 简化版）

## 一、什么是精准测试

精准测试的核心思想：**根据代码变更自动筛选出相关的测试用例，只跑受影响的部分**，而不是每次都跑全量。

### 为什么需要精准测试

- 全量回归越来越慢（1000 条测试跑 30 分钟）
- PR 等待时间长，研发效率低
- 大部分测试和本次改动无关，浪费 CI 资源

### 核心挑战

如何准确判断「代码变更影响了哪些用例」？

### 准确率 vs 召回率的权衡

> **宁可多跑（低精确高召回），也不要漏测（高精确低召回）**
> 漏测的代价 = 线上故障；多跑的代价 = 多等几秒钟

| 指标 | 定义 | 目标 |
|------|------|------|
| 召回率 (Recall) | 精准用例发现的 Bug / 全量发现的 Bug | ≥ 80% |
| 精确率 (Precision) | 相关用例数 / 实际运行用例数 | 越高越好，但不强求 |
| 节省时间 | 1 - 精准耗时 / 全量耗时 | ≥ 50% |

## 二、工业界四层方案对比

| 方案层级 | 技术手段 | 准确率 | 实现成本 |
|----------|----------|--------|----------|
| L1 基础版 | 按模块/文件路径匹配 | 60-70% | 低（1-2周） |
| L2 标准版 | 代码覆盖率 + 用例映射 | 75-85% | 中（1-2月） |
| L3 高级版 | 调用链分析 + 字节码插桩 | 85-95% | 高（团队级项目） |
| L4 智能版 | AI 模型预测 + 历史数据训练 | 90%+ | 很高（平台级建设） |

## 三、本项目选型：L1 简化版

### 选型理由

1. 个人项目，用例数量少（10+ 条），不需要复杂的 L2/L3 方案
2. 实现成本极低（1 天完成）
3. 容易理解和维护，规则透明
4. 有兜底策略，不会漏测关键链路

### 匹配规则表

基于「变更文件路径」匹配「测试用例目录/命名」：

| 变更文件 | 匹配规则 | 对应测试 | 示例 |
|----------|----------|----------|------|
| `app/main.py` | 修改主程序 | 全部接口用例 + 单测 | test_api.py + test_unit.py |
| `app/models/*` | 修改数据模型 | 相关模块的接口测试 | test_items.py |
| `app/utils/*` | 修改工具函数 | 调用该工具的模块测试 | 按工具名匹配 |
| `tests/*` | 修改测试代码 | 被修改的测试文件本身 | 直接跑修改的文件 |
| `*.yml` / `*.md` | 配置/文档变更 | 只跑冒烟集兜底 | smoke marker |
| `.github/*` | CI 配置变更 | 只跑冒烟集兜底 | smoke marker |
| 未匹配的文件 | 保守策略 | 跑全量冒烟兜底 | smoke marker |

### 设计原则

> 简化版的核心思路：按照目录和命名约定做映射。虽然准确率不高（约 70%），但实现成本极低，且容易理解和维护。**关键是要有兜底策略——匹配不到或不确定时，跑全量冒烟集。**

## 四、精准测试流程图

```
输入：两个 commit hash（或 PR 的 base vs head）
  │
  ▼
Step 1：git diff 获取变更文件列表
  │  git diff --name-only base...head
  ▼
Step 2：根据变更文件路径，匹配对应的测试用例文件
  │  遍历变更文件 → 匹配规则 → 收集 test_files + test_markers
  ▼
Step 3：生成 pytest 执行参数
  │  pytest tests/test_api.py -m smoke --alluredir=...
  ▼
Step 4：加上冒烟集兜底
  │  如果匹配结果为空 → pytest -m smoke
  ▼
输出：pytest 命令参数 + 匹配说明
```

### 兜底策略

- 匹配不到任何规则 → 跑冒烟集（`-m smoke`）
- 配置/文档变更 → 跑冒烟集
- 不确定影响范围 → 跑冒烟集
- **核心原则：宁多跑不漏测**

## 五、git diff 常用命令笔记

```bash
# 比较两个 commit 的差异
git diff commit1..commit2 --name-only

# 比较当前分支和目标分支的差异
git diff origin/main...HEAD --name-only

# 只看变更的文件列表（不看具体内容）
git diff --name-only

# 按类型过滤：只看新增/修改的文件
git diff --name-only --diff-filter=AM  # A=新增, M=修改

# 只看删除的文件
git diff --name-only --diff-filter=D

# 统计变更行数
git diff --stat

# 在 GitHub Actions 中获取 PR 变更文件
# github.event.pull_request.base.sha
# github.event.pull_request.head.sha
# 需要设置 fetch-depth: 0 拉取完整历史
```

### 重要坑点

> `actions/checkout` 默认只拉取最新一个 commit（深度为 1），git diff 会找不到 base 分支的 commit。必须设置 `fetch-depth: 0` 拉取完整历史，或者手动 `git fetch origin <base_branch>`。
