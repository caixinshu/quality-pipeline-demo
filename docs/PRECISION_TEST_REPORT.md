# 精准测试准确率报告

## 评估指标定义

| 指标 | 公式 | 说明 |
|------|------|------|
| 召回率 (Recall) | 精准用例发现的 Bug 数 / 全量用例发现的 Bug 数 | 衡量漏测率，越高越好，目标 ≥ 80% |
| 精确率 (Precision) | 相关用例数 / 实际运行的用例数 | 衡量筛选准确度，越高跑的越少 |
| 节省时间 | 1 - (精准耗时 / 全量耗时) | 效率提升比例，目标 ≥ 50% |
| 用例数减少率 | 1 - (精准用例数 / 全量用例数) | 用例规模减少比例 |

> **指标优先级**：精准测试最重要的指标是召回率，不是精确率。漏测的代价比多跑几条用例大得多。

## 评估方法

### 本地评估命令

```bash
cd "f:\apk\其他\todo\quality-pipeline-demo"

# 评估最近一次提交的精准测试准确率
python scripts/evaluate_precision.py --base HEAD~1 --mode diff --output precision-result.json

# 查看 JSON 结果
cat precision-result.json
```

### CI 中评估

PR 流水线的 `precision-test` job 会自动：
1. 运行 `precision_test.py` 筛选用例
2. 运行筛选后的测试
3. 保存 `precision-stats` artifact 供分析

### 如何收集 5 次 PR 数据

1. 创建 5 个不同类型的 PR（修改不同模块）
2. 每个 PR 的 Actions 页面下载 `precision-stats` artifact
3. 记录变更文件数、精准用例数、执行时间
4. 填入上面的数据表

## 改进方向

1. **更细粒度的匹配**：从文件级到函数级
2. **调用链分析**：通过 AST 分析函数调用关系
3. **覆盖率追踪**：用 coverage.py 追踪每条用例覆盖了哪些代码行
4. **历史数据训练**：积累多次 PR 数据后优化匹配规则
