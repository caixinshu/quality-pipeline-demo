# CI/CD 流水线分层设计与质量门禁体系

## 一、四层流水线架构

```
┌─────────────────────────────────────────────────────────────┐
│                     四层流水线架构                            │
├──────────┬──────────┬──────────┬────────────────────────────┤
│  提交级   │  合并级    │  每日级   │  发布级                    │
│ ci.yml   │ pr-      │ daily-   │ release-                   │
│          │ pipeline │ pipeline │ pipeline                   │
│          │ .yml     │ .yml     │ .yml                       │
├──────────┼──────────┼──────────┼────────────────────────────┤
│ push     │ PR       │ cron     │ tag v*                     │
├──────────┼──────────┼──────────┼────────────────────────────┤
│ 单测     │ 冒烟     │ 全量回归  │ 生产冒烟                    │
│ 接口测试  │ 代码扫描  │ 全量扫描  │ 审批+通知                   │
│ 代码扫描  │ 质量门禁  │ 质量门禁  │                            │
│ 覆盖率   │          │ 覆盖率   │                            │
├──────────┼──────────┼──────────┼────────────────────────────┤
│ < 3 min  │ < 8 min  │ < 30 min │ < 15 min                   │
├──────────┼──────────┼──────────┼────────────────────────────┤
│ 快速反馈  │ 质量底线  │ 全面回归  │ 发布验证                    │
└──────────┴──────────┴──────────┴────────────────────────────┘
```

## 二、设计原则

1. **频率与范围成反比**：触发越频繁的流水线跑得越少越快
2. **渐进式保障**：从单测到冒烟到全量，覆盖范围逐步扩大
3. **快速失败**：任何一层发现问题立即阻断，不浪费后续资源
4. **灰度接入**：新工具先用 `continue-on-error: true` 接入，不阻断

## 三、质量门禁体系

### 三条核心门禁

| 门禁 | 阈值 | 阻断层级 | 实现方式 |
|------|------|----------|----------|
| 通过率门禁 | 100% | 合并级 | `quality_gate.py --junit` |
| 覆盖率门禁 | ≥ 70% | 提交级 | `pytest --cov-fail-under=70` |
| 安全扫描门禁 | High ≤ 0 | 合并级 | `quality_gate.py --bandit` |

### 门禁脚本

`scripts/quality_gate.py` 支持三种参数：
- `--junit <path>`：检查测试通过率
- `--bandit <path>`：检查安全扫描结果
- `--skip`：白名单跳过（配合 PR label 使用）

## 四、用例分级策略

| Marker | 范围 | 运行层级 | 数量 |
|--------|------|----------|------|
| `@pytest.mark.smoke` | 核心链路 | 合并级 PR | 2 条 |
| `@pytest.mark.regression` | 全量回归 | 每日级 | 全部 |

### 划分标准
- **冒烟用例**：服务能否启动、核心 API 能否正常调用
- **回归用例**：边界值、异常输入、负数、字段缺失等

### 维护规则
- 新增 API 必须同时新增冒烟用例
- 冒烟用例数量控制在总用例的 20-30%
- 回归用例持续积累，不删除

## 五、CI/CD 最佳实践总结

1. **缓存优先**：pip cache + docker layer cache 可节省 50%+ 执行时间
2. **并行优于串行**：无依赖的 job 并行跑
3. **超时保护**：每个 job 设 `timeout-minutes`，避免卡死
4. **if: always()**：报告上传和清理步骤必须执行
5. **continue-on-error**：新工具灰度接入，不阻断流水线
6. **分支保护**：main/develop 必须走 PR，不能直接 push
7. **环境隔离**：发布级用 `environment: production` + 审批人
8. **Artifacts 保留**：测试报告保留 90 天，方便回溯
